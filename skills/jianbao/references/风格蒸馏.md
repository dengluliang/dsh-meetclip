# 发布会文档风格蒸馏 v1

> 蒸馏对象：邓璐良 2025–2026 年「手机新品发布简报」知识库 43 篇文档中的 **34 篇人类稿**（可读 33 篇）。
> **排除项：9 篇 AI 版（【AI 生成】/【AI 帮看版】/【AI 完成】）不作为风格来源**，避免把 AI 稿的写法当成你的风格。
> 蒸馏方法：飞书开放接口只取纯文本 + 块结构（丢弃图片 alt），再统计骨架/模块/图表基线，最后抽 12 篇深读句式。
> 用途：作为 `发布会图文简报` skill 的写作规范来源。**这是风格事实的沉淀，不是提示词。**

## 0. 一句话结论

你的发布会文档是**两套不同体裁**，不是一套：

| 族 | 适用 | 骨架 | 篇均图 | 特征 |
|---|---|---|---|---|
| **A 产品族**（23/42） | 手机 / 穿戴 / 平板 / IoT 新品发布 | `概述 › [产品概要] › 价格 › 参数表 › 发布会详情` | 100–370 张 | 参数与价格是硬骨架，正文按机型×卖点展开 |
| **B 生态族**（VDC / ODC / Google I/O / HarmonyOS） | OS、开发者大会、战略发布 | `概要 › 舆情与讨论 › 发布会关键信息提要 › … › 安全人文生态` | 24–299 张 | 有「舆情」「行业反应」「对小米的影响判断」等分析模块 |

把 B 族硬套 A 族骨架（或反之）会立刻“不像你写的”。skill 必须先判定体裁再选骨架。

## 1. 量化基线（33 篇人类稿块结构统计，已剔除 AI 版）

- 篇均：标题 **9.5** 个 / 图 **166** 张 / 图组（grid）**43.7** 个 / 原生表 **3.2** 个 / callout **1.2** 个
- 图片中位数 **145** 张，区间 22–368（三星 S25 nano 22 张；华为 Pura X Max 368 张 / 98 图组）
- **图是主体，不是点缀**：手机族基本每 3–5 行文字就跟 2–4 张图，`<grid>` 2–4 列为主
- 层级命名与信息量正相关：`nano ⊂ lite ⊂ 信息提要 ⊂ 简报 ⊂ 信息汇总`
  - 人类稿实测规模：简报 14 篇 / 信息提要 9 / lite 8 / fast 1 / 信息汇总 1 / nano 1
- 标题格式统一：`厂商 + 机型/主题 + 层级 + | 或 ｜ + MMDD`（带 `【AI 生成】/【AI 帮看版】/【AI 完成】` 前缀的一律不作为风格来源）

## 2. A 族（产品发布）骨架——逐段规格

### 2.1 顶部 callout
每篇第一块固定是一个 callout，含两样东西：
1. 年度汇总文档的引用（`2025年手机发布会简报汇总` / `2026年…`）
2. **发布会全文转写链接**（`https://d.biji.com/xxx`），手机与 IoT 分场时列两条

> 我们的 skill 改为：引用汇总（可配置）+ **会摘记录链接/时间戳**。这是“可溯源”的落点。

### 2.2 `概述`（最高价值模块）

33 篇人类稿逐字比对后的**实测模式**（不是概括，是可核对的写法）：

1. **多组「标签 + 加粗一句定性」**，标签按本场重点自定义，**不固定三个**。出现过的标签：`产品：`、`讲述：`、`传播&讲述：`、`硬件：`、`影像：`、`AI：`、`价格：`；也有问答式（Mate80：`什么芯片？` / `多少钱？`）。
2. 每组标签下 **3–6 条**，逐机型／逐能力分条，**每条都带具体参数与对比基线**。
3. 子项可再嵌套一层（vivo X500 的 Pro 条目下继续展开）。
4. 定性句的常见句式：`本质是…`、`从 X 调整为 Y`、`X 下放 / 换 / 取消`、`两杯共享…真正拉开差距的是…`。

原文示例（可直接对照体例）：

- vivo X500：「**产品：**整体升级乏善可陈，标准版留守 n-1，Pro 大小杯强行提档（6.3"标准/Pro mini➡️Pro，Pro➡️Pro Max）」
- Pura X Max：「**硬件：**Pura 90 变阵求生，Pura X Max 抢先「果叠」」+「直板新摆阵：nova Ultra ➡️ Pura 标准；Pura 标准 ➡️ Pura Pro；Pura Pro ➡️ Pura Pro Max；取消 Ultra」
- OPPO Find X9：「**产品：**标准版常规改款，Pro「存在感」大增，Pro 1TB 独占 eSIM+天通」

5. **呈现形式**：历史文档用的是普通段落 + 列表；**本 skill 按用户要求改为整体放进 `<callout emoji="💡" background-color="light-blue">`**（高亮块内只支持文本/标题/列表，不能放表格与图片）。
6. **禁止**：本项目已约定不写主观贬褒与传闻，所以概述里的“定性”只能落在**事实层定性**（结构、换代关系、价格变化、篇幅分配）。历史稿里的「乏善可陈」「像素级抄袭」不得沿用。

### 2.3 `产品概要`
`产品名称 / 发布时间 / 产品 Slogan` 三行式（人类稿写法；同场还有其他新品时追加一行「同场新品」）。

### 2.4 `价格`
每机型一张小表：容量 → 价格，无表头行。特殊 SKU（卫星版、典藏套装、线上专属款）单列并注明差异。

### 2.5 `参数表`
- 表头：`参数项 | 本代 | ↑ 上代`（可再加一列竞品）
- 行项目顺序稳定：颜色→处理器→内存→前置→后置→屏幕→厚度→重量→电池→充电→音频→连接→马达→起售价
- 升级用 `↑` 或加粗，退步用 `↓`；只有单侧变化时另一侧写 `—`
- 若参数来自发布会口播而非官网，必须标注来源（口播 / 官网 / 参数墙）

### 2.6 `发布会详情`（正文主体）
- 二级标题 = 机型 / 环节；三级标题 = **沿用官方卖点名**（`Super 设计`、`超Super 影像`、`灵盾防窥屏`），不自创分类
- 小节内容：3–8 条极简 bullet（关键词+数字+对比），**bullet 后紧跟该小节的 `<grid>` 图组**
- 讲者与环节切换必须标注：`何刚主讲`、`导入环节：直接让田曦薇上场`、`换人讲`、`巡回返场`
- 现场事件也要记：口误、站台嘉宾、供应商团建、One More Thing

### 2.7 尾部
配件与权益（壳/膜/耳机/延保 + 价格 + 渠道 + 开售时间）、生态合作、下一场预告。

## 3. B 族（OS / 生态发布）骨架

实测三种写法，越靠后越像“情报分析”：

1. **VDC / ODC 型**：`一、概要 ｜ 二、舆情与讨论 ｜ 三、发布会关键信息提要（slogan / 导入 / AI战略 / 系统发布）｜ 四、BlueOS ｜ 五、安全、人文与生态`
2. **Google I/O 型（最完整）**：`整体概要 ｜ 一、战略定调 ｜ 二、AI 能力框架（分 N 个能力小节）｜ 三～八、各产品线 ｜ 九、行业反应与评价（高管表态 / 媒体 KOL / 社交 / YouTube）｜ 十、对小米的影响判断 ｜ 附：传播时间线`
3. **HarmonyOS 7 型（fast）**：`发布会概述 ｜ 讲述（含时间分配占比）｜ 价格 ｜ 产品参数 ｜ 发布会详情（按环节编号）`

B 族的独有模块（A 族没有）：
- **时间分配**：`全场 174 分钟，自动切分 58 段：HarmonyOS 7 约 24min 占 14%…`
- **战略定调**：`Android 从 Operating System 转型为 Intelligence System`
- **能力清单化**：把发布会内容归纳成 6 项能力，而不是复述顺序
- **行业反应 / 舆情**：媒体、KOL、社交、测评四路
- **对小米的影响判断**：逐维度分析 + 核心结论 + 后续关注节点

## 4. 转写特有的纪律（本 skill 新增，不来自现有语料）

0. **存疑不进正文**：任何“不确定的专名/数字”先问用户澄清；未澄清则用通称或省略。成稿里不出现「待核实」「存疑」字样（用户 2026-11-09 定）。

我们的原料是转写而不是现场笔记，因此必须补三条纪律。**这不属于“参考 AI 版”，而是基于转写的客观需要**：

1. **ASR 存疑标注**：转写中出现明显不通、数字异常、专名可疑时，保留原文并标疑，不许默默改写。
   例：`「加之 490,000 元」// 疑为转写错误，应为「价值 490 元」，待核实`
2. **来源分层**：口播 / 发布会画面（PPT） / 官网参数 / 会后补充，四类来源不混写；转写只能支撑前两类。
3. **不确定词**：`疑似` / `待核实` / `官方称` / `（未说明）`——只用于事实不确定，不用于观点表达。

## 5. 明确不保留的东西（用户 2026-11-09 决定）

历史文档里存在大量主观判断，**新 skill 一律不写**：

- ❌ 贬褒形容词：`硬件乏善可陈`、`常规到不能再常规`、`不知道为啥要吹的一堆老功能`
- ❌ 抄袭/致敬类定性：`像素级复刻 Reno`、`把田曦薇当宋雨琦用`、`截胡之心昭然若揭`、`抄袭对象变了`
- ❌ 行内吐槽：`// 但实拍效果很差`、`// 谁问你了`、`// 但表单上看，时长其实差挺多的`
- ❌ 未证实传闻：`据传 v 看到 O 的动作后紧急提拉明星需求`、`疑似为主力出货版本`
- ❌ 竞品优劣结论：`对比 LOFIC 劣势：依然无法解决动态鬼影`

替代写法：把判断转成**可比对的事实**。例：
- 原：`传播和发布会像素级抄袭 Reno，明星上场的节奏控制都复刻`
- 新：`篇章结构为「外观 + 影像 + 体验」三段式；明星在开场与影像部分两次出场；同结构见 OPPO Reno15（引用链接）`

## 6. 图片规格（决定“图文并茂”成败）

- 数量基线：篇均 166 张（中位数 145），但那是人工逐张挑的。skill 目标 **每小节 2–4 张，全文 40–80 张**
- **排布必须分列**：用 `<grid cols="2">` 或 `<grid cols="3">` + `<column>`，同一卖点的图**并排一行 2–3 张**；禁止把图竖排成一列（实测：竖排会让每张图占满宽度，一屏只能看一张，节奏完全垮掉）
- 单张图的小节可直接 `<image>` 直出，不必套 grid
- 归属判定：用转写时间戳把小节与画面区间对齐，区间内的变化帧才进该小节
- 只保留“画面有明显变化”的帧（PPT 翻页/演示切换），同一页持续讲解只留 1 张
- 图注：`卖点名 @MM:SS`，**不做 AI 画面描述**（用户明确要求：图片只是配合，不要看图总结）

## 6.5 新增的本地约定（用户 2026-11-09 要求，非历史体例）

- 文档开头嵌入**源视频播放器**（B 站 `<iframe type="1"/>`），并紧跟一张**回看索引**表：小节 + 时间区间 + `源地址?t=秒` 可点跳转
- 文档内**不出现**与发布会无关的信息（会摘记录 id、转写段数、截图数、文件名、工具名）
- 未确认的专名/型号**不写进正文**，先问用户；成稿只含确认信息

## 7. 对 skill 的直接约束（结论）

1. **先判体裁**，再选 A 族或 B 族骨架。
2. **概述必须是标签化三段**（产品/讲述/价格），全部由转写事实支撑。
3. **每个事实句都要能回答：谁说的、什么时候说的、原话是什么**。
4. 参数表与价格表优先于叙述；发布会没讲清的参数留 `（未说明）`，不许猜。
5. 图只做配合，按小节时间区间自动配，不做视觉理解。
6. 结论文档末尾附「素材与时间戳索引」，让读者能回到原片核对。
