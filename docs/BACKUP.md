# 备份与迁移

设置 → 会摘 → **备份** 把选中的卡片打包成一个 zip，交给另一台电脑（或另一个人）导入。
备份按**卡片**选择：记录、卡包（卡片组）、便利签、标记、图片、飞书文档、批次视频都可以单独勾选，
也可以全选；选中卡包/批次/标记时，它们依赖的记录与卡片会一起带走。

## 导出

1. 打开 **设置 → 备份**，页面先读取当前资料空间里所有可备份的卡片。
2. 勾选要备份的卡片；`全选 / 清空 / 搜索标题 / 按类型全选` 都在这一页。卡包行会展开显示成员。
3. 需要连视频/音频一起带走时勾选 **包含视频/音频文件**；默认不带，体积会小很多。
4. **导出到** 默认是 `<资料库目录>/备份/`，可以点「更改…」换位置。
5. 点「导出备份」后后台打包，页面显示阶段、百分比与已写字节，可取消；完成后显示文件路径、大小与
   SHA-256，可「在 Finder 中显示」。

导出文件名：`MeetClip备份-YYYYMMDD-HHmm.zip`（同一分钟重复导出会追加 `-2`、`-3`）。

- 正在采集/排队中的记录导出**当前已写入的内容**，并且**不包含它的媒体**；清单里会留一条 warning。
- `asr_chunks/`、`source/`、`export/` 等中间产物不会进备份：它们是可再生成的临时文件。
- 备份**不含**账号 Cookie、`settings.json`、模型 Key、`.api-token`、本机绝对路径。

## 导入

1. 在目标电脑切到要导入的**资料空间**（设置 → 资料空间），再打开设置 → 备份。
2. 「选择备份文件…」选 zip（也可以手动填写路径后点「读取」）。
3. 会先读出清单：来源资料空间、导出时间、会摘版本、各类卡片数量、是否含媒体、这个备份里
   已导入过多少张卡片，以及导出时的 warning。**这一步不写资料库**。
4. 可选 **导入视频/音频**（备份含媒体时才有）与 **跳过已导入的卡片**（默认开）。
5. 点「开始导入」，后台解包并写库，显示阶段与百分比；完成后显示导入数量与跳过数量。

导入规则：

- 记录、便利签、图片、卡包一律分配**新标识**；标记是自增 id，会建立旧→新映射，卡包成员跟着改。
- 批次视频按整批恢复时换新批次 id；只导入部分成员时会剥掉批次归属，按单条记录显示并提示。
- 未完成状态的记录归一为终态：有转写记 `done`，没有转写记 `cancelled`，不会卡在「处理中」。
- 导入后调用卡片的幂等同步，`@` 菜单与首页立即出现新卡片；不重启引擎、不刷新页面（首页会收到刷新信号）。
- 文档卡按 `doc_type:token` 键登记：目标资料库已经有同一篇文档时保留现有正文快照，不覆盖。
- 卡包成员已在目标库的其它卡包里时跳过该成员并汇总提示；成员全部失效时不建空卡包。

去重键是 `(archive_id, item_type, item_id)`，记录在资料库的 `backup_import_items` 表里。
同一份备份重复导入默认全部跳过；取消「跳过已导入的卡片」可以再存一份（新标识），
但旧的去重记录会保留第一次导入的映射。

## 文件格式 v1

普通 zip，根目录有 `manifest.json`：

```json
{
  "format": "meetclip-backup",
  "format_version": 1,
  "archive_id": "<uuid4>",
  "created_at": 1763340000.0,
  "app_version": "0.9.18",
  "source": { "library": "工作" },
  "options": { "include_media": false },
  "items": [
    { "type": "pack", "id": "81a26c275e57", "title": "miloco 3.0 相关讨论", "member_count": 5 },
    { "type": "session", "id": "1f27140d1c76", "title": "IMG_1302", "kind": "meeting" }
  ],
  "counts": {
    "records": 3, "transcripts": 736, "screenshots": 0, "marks": 0,
    "minutes": 3, "notes": 0, "images": 0, "docs": 2, "packs": 1,
    "batches": 0, "highlights": 0
  },
  "warnings": []
}
```

目录结构：

```
manifest.json
README.txt                       一句话说明怎么导入
records/<记录id>/record.json     session 行 + transcripts/screenshots/marks/minutes/interactions
records/<记录id>/shots/<文件名>   截图（始终带）
records/<记录id>/media/<文件名>   媒体（仅 include_media=true；正在采集时跳过）
records/<记录id>/cover.jpg       存在则带
notes/<便利签id>.json
images/<图片id>.json
images/files/<文件名>
docs/<文档key>.json              含登记时读到的正文快照
packs/<卡包id>.json              成员用 type + id 引用
```

`record.json` 里的 `session.media_path` 只写安全文件名；`session.media_included` 说明这条记录是否带媒体。
导入端只用**校验后的数据库派生文件名**去 zip 里取文件，不会把 zip 条目名直接当路径。

卡包成员类型：`session / batch / highlight / note / image / doc`。导出时文档成员的 id 存成裸 key，
导入时会补回 `doc:` 前缀；标记成员用数据库里的整数 id，导入时映射成新 id。

## 安全与限额

- 只接受回环地址 + 本地 API token 的请求；导入路径必须是已存在的绝对路径。
- zip 条目 ≤ 50,000；单条目解压 ≤ 20 GB；总解压 ≤ 100 GB；压缩比 > 1000 且 > 1 GB 直接拒绝。
- 条目名拒绝绝对路径、`..`、反斜杠与控制字符；`format_version > 1` 会提示先升级插件。
- 导入先落文件再单事务写库；失败/取消会删掉本次新建的目录与图片，数据库不留半条记录。
- 启动时清理上次异常中断留下的导入目录（只删带 `.backup-import` 标记、且数据库里没有记录的目录）。
- 有备份任务在跑时切换资料空间会要求确认；确认后先取消任务再切，避免半份导入。

## 排错

| 现象 | 处理 |
| --- | --- |
| 「这个文件不是有效的会摘备份」 | 选错文件，或文件被截断；重新导出/传输 |
| 「备份来自更新版本的会摘」 | 先升级插件再导入 |
| 「磁盘空间不足」 | 换目标位置，或取消勾选「导入视频/音频」 |
| 导入后记录没有视频 | 备份导出时未勾选媒体，或导出时记录正在采集；重新导出一份 |
| 导入后文档卡是「仅链接」 | 导出时文档卡本身没有正文快照（只登记过链接） |
| 卡包少了成员 | 成员已在目标库其它卡包里，或该成员属于没有导入成功的卡片 |
| 重复导入没有新增 | 默认按 archive_id 去重；取消「跳过已导入的卡片」再导入 |

## 版本与兼容

- `format_version` 目前是 1，字段只增不改；更高版本会明确拒绝，不做猜测性读取。
- 备份可跨资料空间导入，但**一次只写当前激活的资料空间**；不合并、不覆盖整库。
- 插件更新不会影响已导出的备份；旧备份仍按 v1 读取。
