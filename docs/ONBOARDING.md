# 会摘首次配置与账号登录旅程

首页 Hero 对话框保持现状：输入文字/链接仍发给 Agent。本文件只记录「需要人填、人扫、人授权」的旅程。

## 1. 模型服务

```
设置 → 模型 / 首页配置进度 / 首次引导
  → 填服务地址（Base URL）
  → 粘贴 API Key
  → 连接并获取模型（Host 探针，不要求先保存）
  → 选语音转文字、文字总结
  → 一次保存并测试
```

- 不再有「保存地址要先有模型、选模型要先有地址」的死锁。
- 自定义 API 在「高级」里，互不覆盖。
- Key 只进钥匙串，不写 localStorage/sessionStorage。

## 2. 首次引导

- 第 1 步：连接模型；「跳过」始终可用。
- 第 2 步：存储位置 + 安装；可上一步、取消安装；完全磁盘访问可一键打开；刷新/重开接回后台任务。
- 第 3 步：运行环境/采集组件/云端转写/存储位置四项状态 + 修复入口；可选账号；四条「现在试一次」。

## 3. 账号

| 账号 | 入口 | 步骤 | 成功后 |
|---|---|---|---|
| B 站 | 设置 → 账号 | 扫码；或读取 Chrome 登录态 | Cookie 同时用于直播与视频链接 |
| 抖音 | 设置 → 账号 | 选浏览器 → 打开登录页扫码 → 读取登录状态 | 写入专用 Cookie；可粘链接测试 |
| 飞书 | 设置 → 飞书 / 账号 | 安装 MCP → 登录（浏览器或设备码）→ 验证读取文档 | 状态显示「可以使用」；否则「已连接，建议试读」/「登录待刷新」 |

## 4. 失败后的动作

- B 站会员/风控/私享：就地二维码 + 「登录后重试」；技术原文折叠。
- 抖音 Cookie/权限：三步登录卡 + 「打开完全磁盘访问设置」。
- 飞书 access token 过期：`feishu_token_expired`，登录/设备码/仅登记链接。
- 模型/引擎/存储：错误旁给配置入口；设置从覆盖层打开，不丢已贴链接。
- 首页对话框贴飞书链接：Agent 调 `meetclip_capture add_doc`；未登录时如实转述，或只登记链接。

## 5. 验收要点

- 全新环境跳过 Key 后，设置 → 模型能完成一次配置，不出现「请先填写模型 ID」。
- 安装中刷新，回到后台进度而不是第 1 步。
- B 站视频失败 → 就地扫码 → 自动重试成功。
- 抖音新用户能按三步完成，不需要先有历史链接。
- 飞书必须能试读一篇文档才算可用。
