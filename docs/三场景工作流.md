## 1. 三条链路共同的骨架

```
新建采集（三个页签）
   → 写记录（sessions 表）→ 任务入队（task_queue）
   → scheduler 单线程出队（全局同一时间只跑一个任务）
   → 管线执行（capture / meeting / link_video）
   → 状态写回 sessions / link_jobs，SSE 推给详情页
   → 详情页：播放、转写、标记、笔记、纪要、导出
```

- **队列是全局单槽位**：会议转写在跑时点“开始直播”，直播会先 `queued`，轮到才真正开录；链接同理。
- **排队可取消**：取消只删队列项并置 `cancelled`；已开跑的任务取消会保留已采集/已下载内容。
- **实时刷新**：活动任务通过 `GET /api/sessions/{sid}/events` 走 SSE；任务结束后详情页退回轮询。
- **所有场景共用的事后能力**：标记（M）、笔记（Markdown + 版本 CAS）、记录内查找（⌘F）、全局搜索、改名、复制（链接除外）、删除（进废纸篓/应用内 `.trash`）、导出、重新转写。

## 2. 直播（live）

```
输入直播间 URL
  → 700ms 防抖预检 POST /api/precheck
  → 只有预检 ok 才可点「开始直播」
  → POST /api/sessions（再查一次房间）→ POST /start → 入队
  → 队列轮到：capture.CaptureTask
      ├─ 解析流：Chrome 登录 Cookie 取 B站原画；失败回退 yt-dlp（常见 720P 降级）
      ├─ ffmpeg -re 录 media.ts，同时写 live/index.m3u8（边录边看）
      ├─ 2fps 画面检测 → 自动截图 shots/*.jpg（最多 5000 张）
      └─ 100ms 音频 → 按停顿切块 → ASR 队列 → transcripts（SSE 即时出现）
  → 停止 / 直播流结束：
      收尾 ASR → TS 转 MP4 → 按最后一次说话位置裁尾部 → status=done
```

### 2.1 预检（只支持 B站直播）
- 识别 `live.bilibili.com/房间号`、纯房间号、`b23.tv` 短链（跟随跳转）。
- 返回：标题、封面、主播、分区、开播时间、状态。
- `live_status`：`1` 直播中（ok）；`2` 轮播/回放（拒绝）；`0` 未开播（拒绝）；接口不可达也拒绝。
- 先建记录、后启动；启动时状态已变化/接口失败会留下记录，可稍后从详情页再点“开始”。

### 2.2 采集
- 画质：登录 B站后走原画；未登录会提示“最高 720P”，实际质量写入记录并在信息页显示。
- 直播流中断/主播下播：ffmpeg 自然收尾，仍按“停止”路径落盘。
- 录制期间可拖动时间轴、看 HLS 预览（不支持 MSE 时退回 1fps 预览图）。

### 2.3 实时转写
- 音频按 100ms 帧读入，静音 ≥4 秒或累计 15 秒切一块；静音块不进 ASR。
- 只走 MiMo 云端（本地 Qwen3-ASR 已下线）；直播这条链路**不传热词/上下文**，也**不做说话人分离**。
- 转写随识别完成逐条写库并 SSE 推送；时间戳是块边界（片段级），不是词级。
- 模型未启用：媒体照常保存，转写标记 `skipped`，之后可“重新转写”。

### 2.4 截图（只有直播有）
- 检测帧率 2fps，黑屏跳过；按“与上一参考帧的差异”判定；灵敏度设置映射成阈值。
- 命中后从同时间点取原分辨率帧，自动裁掉竖屏黑边/上下黑边后存 `shots/`。
- 两次截图有最小间隔，稳定画面或持续变化 3 秒后各触发一次；上限 5000 张（到 4500 提醒）。
- UI 只有“灵敏度滑杆”，**没有手动截图按钮**；截图没有 OCR（见 §6）。

### 2.5 结束
- 手动停止：`POST /stop`；已排队未开录则直接出队。
- 自动结束（0.4 才有）：按“识别出的词”计时，默认连续 600 秒没有词 → 发 `end_prompt` 询问，60 秒倒计时；点“继续记录”重置；一直没人说过话则静默结束；结束按最后一次说话位置 +2 秒裁尾。
- 取消：立即终止，保留已录内容并置 `cancelled`。
- 收尾阶段在 UI 显示：结束直播流 → 生成回放文件 → 完成转写 → 已保存。

### 2.6 事后
- 播放 MP4（remux 失败则保留 TS）。
- 标记可在录制中或回看时添加；笔记随时可写。
- 纪要（0.4）：录制中每 ≥120 秒增量更新（模式 `live`），结束时终稿；需 AI Key。
- 导出：0.3 只有 Markdown/ZIP；0.4 另带 SRT/VTT/DOCX。

## 3. 链接视频（link_video）

```
一行或多行 URL（≤50 条；入口自动跳过格式错误/不支持/重复）
  → 逐条 POST /api/link-videos/preview（yt-dlp 预读）
  → 显示标题/时长/大小/平台/字幕轨；可改「字幕优先」或「云端 ASR」
  → POST /api/link-videos/batch（规范化 URL、平台校验、去重、≤50 条）
  → 多条提交写 meta.batch，首页聚合为一张批次卡（成员单卡从墙面隐藏）
  → 入队 LinkTask
      准备：读预读缓存或重新探测；时长 ≤6 小时；磁盘检查
      字幕优先：先抓平台字幕 → 直接转成 transcripts（几秒可见）
      下载：yt-dlp（Cookie/登录回退、X syndication 回退）→ media.mp4
      没有字幕：抽音频 → 复用会议离线转写管线
      下载失败：重试；仍失败可「内录」共享窗口/屏幕 → webm 上传 → 会议管线转写
  → status=done
```

### 3.1 预读
- 支持平台：B站、微博、抖音、YouTube、X（Twitter）；其他链接直接拒绝。
- 返回时长、文件大小、上传者、字幕轨（人工/自动/翻译）及默认轨。
- URL 规范化：X 统一到帖子 ID、去掉追踪参数；重复链接用规范化 URL 查重，默认不允许重复。
- 单条最长 6 小时、缓存上限 8GB；X 帖子无视频会保留原始错误。
- 登录受限时按设置读取浏览器 Cookie；失败给出“需要登录/检查权限”类错误。
- 抖音：yt-dlp 的 Douyin 提取器要求浏览器 Cookie；未导入时提示“需要登录”。设置 → 采集 → 视频可打开抖音登录页，扫码登录后「读取浏览器 Cookie」写入 `data/douyin_cookies.txt`，链接管线对抖音优先使用该文件；平台风控仍可能导致失败。

### 3.2 字幕优先
- 只有预读发现字幕且模式为 `auto` 才走字幕；多轨时必须选语言，否则批量入口拒绝该条。
- 字幕直接写成转写行，`transcription_source=subtitle`，**没有说话人**，时间轴用字幕时间。
- 没字幕或选 `asr`：下载后走会议同款离线转写（0.3 会按勾选做说话人分离）。

### 3.3 下载与兜底
- yt-dlp 先匿名、失败再按授权读 Cookie；X 额外走 syndication 公共端点。
- 下载进度通过 SSE 推给详情页；可取消，已下载内容保留。
- 下载失败（`job_state=error`）后详情页出现“重试 / 内录”：
  - 内录用浏览器 `getDisplayMedia` 共享窗口/屏幕，录 webm → Host 上传 → 后端交给会议管线转写 → 回写为 done。
  - 内录会预占单槽位；停止录制则置 `cancelled`。
- **链接入口不拦截 B站直播链接**：预读只带回 `live_status`，批量仍会接受；这类链接会按普通视频下载，存在一直录到 8GB 上限才停的风险。

### 3.4 事后
- 播放 MP4；无截图、无 HLS、无自动结束。
- 标记/笔记/搜索/导出同通用能力。
- 重新转写会强制改回 `transcription_mode=asr`（放弃字幕来源），从头跑 ASR。
- 纪要（未发布）：字幕路径已在 `LinkTask` 收尾时补 `minutes.finish()`，转录完成自动生成终稿；ASR 路径仍由会议管线触发，两条路径都不会重复排队。

### 3.5 批次卡
- 一次提交超过 1 条链接且至少创建 1 条时，后端生成 `batch_id`，把 `{id,title,created_at,updated_at,total,index}` 写进每条记录的 `meta.batch`。
- `GET /api/home` 额外返回 `batches`：成员按提交顺序、状态计数、平台分布、`active` 数；排序用 `updated_at`（没有追加过时等同创建时间），刚续加过的批次回到最前。
- 首页把批次成员从墙面聚合掉，只显示一张批次卡；点开浮层可看成员状态/错误并进入单条记录。
- 提交后自动定位：信息流滚动到卡片，散落模式相机飞到卡片中心，并短暂高亮。
- 单条提交不生成批次卡，保持原有单卡行为；成员被删除后批次自然收缩，全部删除则卡片消失。

### 3.6 批次连续添加与续排
- 视频表单一次提交出批次卡后**不关闭**：已加入的行从输入框移除，失败/重复行保留；继续贴下一批即可创建下一张批次卡，点「完成」才关闭并定位最近一批。
- 全部重复/失败时后端回 400，但返回逐条 `results`；前端把它渲染成结果列表，并提供「仍然加入重复链接」（按 `allow_duplicate=true` 重提这些行）。
- 批次浮层「批量加入新链接」和批次卡右键「加入新链接」会带 `batch_id` 调 `POST /api/link-videos/batch`：新记录续排到原批次（`index` 从 `last_index+1` 开始，`total`/`updated_at` 更新），不会另开批次卡；单条也允许续排。
- 批次不存在（例如成员全被删除）时返回 404「批次不存在或已删除」，前端提示刷新后重试；同一条链接仍在的重复检查保持原样，需要确认才能再次加入。

## 4. 会议（meeting）

```
选择本地文件（原生选择器）或拖拽上传（≤8GB）
  → POST /api/meetings/import（标题/语种；热词仅接口保留）
  → 入队 MeetingTask
      复制到记录目录 → ffprobe 探测 → 统一转成可回放格式
      → 抽 16k 单声道 wav → 语种检测 → 整段离线转写
      → 0.3：可选词级对齐 + pyannote 说话人；失败自动去掉说话人重跑一次
      → 按句尾/停顿合并段落
      → transcripts 落库，status=done
  → 0.4：结束时排 AI 纪要终稿
```

### 4.1 入口
- 支持 mp4/mov/mkv/flv/webm/m4v/ts 与 mp3/m4a/wav/aac/flac/ogg/opus；单文件 ≤8GB，磁盘至少留 512MB。
- 两种来源：Host 原生文件选择器；或拖拽上传到 `<stateDir>/uploads` 再导入。
- 选项：标题（默认文件名）、语种（自动或指定）。热词输入已从导入卡片移除，接口仍接受 `hotwords` 字段。
- MiMo 云端不支持热词（接口未确认），本地引擎才真正把标题+热词作为上下文。

### 4.2 转写
- 整段离线；先按前 30 秒检测语种（未指定语种且带上下文时）。
- 0.3 运行版：有词级对齐模型时输出词级时间戳；勾选说话人时调 pyannote，得到“发言人 1..N”，分离失败会自动重跑成无说话人版本（不丢转写）。
- 0.4 源码：没有传 `aligner` 和 `diarize`，即使勾选“区分说话人”也不会产生说话人标签，时间戳退回句级/片段级（见 §6）。
- 进度阶段：0.3 为 提取音频 → 转写 → 区分说话人/整理段落 → 完成；0.4 少了 diarize 阶段。

### 4.3 事后
- 发言人改名/合并/撤销（0.3 用 `PATCH /speakers`；0.4 另有“从对话里认人”，需要 AI Key，且至少两个说话人各说满 5 句）。
- 转写选项可改引擎/语种/热词/说话人；引擎或语种变了会从头转，否则只补缺失片段。
- 纪要（0.4）：结束时终稿。
- 无截图、无 HLS、无自动结束（会议是文件，不涉及）。

## 6. 实际实现与“看起来有”的差异（重点）

### 6.1 0.4.0 会议/链接的“区分说话人”实际不生效
- 表单会收 `diarize`、接口会校验并保存到 `meta`、UI 也有发言人页签，但：
  - `backend/app/meeting.py:34` 的 `transcription_params()` 只返回 `language/hotwords`；
  - `backend/app/meeting.py:297` 调 `transcribe_long(...)` 时没有传 `aligner` 和 `diarize`；
  - `LinkTask` 复用同一个 `MeetingTask`，所以链接的 ASR 路径同样没有说话人。
- 结果：会议/链接转写的 `speaker` 全是空；发言人页签为空；“从对话里认人”直接跳过；导出没有“参会人/说话人”段落。
- 证据：运行版（0.3）的会议记录 `7f7db38dafd6` 转写里明确有“发言人 1–4”；而 0.4 源码这条路径不会产生标签。
- 测试也还是旧口径（`backend/tests/test_link_video.py` 断言 `kwargs["diarize"]`），说明 0.4 的测试与实现已经不同步，不能拿测试通过当真机验证。

### 6.2 截图 OCR 并不存在
- 两版都没有任何 OCR 调用；`screenshots.ocr_text` 只有建表、搜索和标签，没有写入方。
- 所以“自动截图、OCR”里的 OCR 部分不可用；全库搜索的“截图文字”命中来源永远为空。
- 截图只对直播有；会议/链接没有截图。

### 6.3 GUI 仍是 0.3.0
- 安装 profile 的依赖是 `MeetClip-0.3.0/*.tgz`；安装目录的 client.js 无纪要/内录/自动结束代码；后端没有 `minutes.py`、`export_srt.py`。
- 因此“设置 → 会摘 → 模型”、AI 纪要页签、SRT/VTT/Word 导出、自动结束、浏览器内录按钮，现在都还看不到。

### 6.4 链接字幕路径的自动纪要（已修复）
- 0.4 只有 `MeetingTask` 结束时调 `minutes.finish`；字幕导入是 `LinkTask` 自己做的，没有调用。
- 未发布版本在 `LinkTask` 成功收尾、`imported` 为真时补 `minutes.finish()`；ASR/内录路径仍由 `MeetingTask` 触发，避免重复。
- 终稿会按视频模板写入笔记；录制/转写中的旧纪要段落保留到新终稿替换。

### 6.5 新建面板不保留草稿
- 只记住上次页签和默认类型（`localStorage`）；关闭弹窗后 URL/文件/热词都不保留，与“采集草稿保留”的说法不符。

### 6.6 直播链接可以从“链接”入口进
- 预读只返回 `live_status`，不做拦截；批量会接受，随后按普通视频下载，可能一直录到 8GB 上限。直播应走“直播”页签。

### 6.7 其他使用预期
- 全局单槽位：直播开始会被正在跑的会议/链接转写挡住，状态先 `queued`。
- 直播说话人：没有；直播热词：没有。
- 纪要需要 AI Key；直播增量默认 120 秒一次、每次最多 200 行，长会议终稿分窗，费用/耗时会高于一次全量。
- 5000 张截图上限、2fps 检测、无手动截图按钮。
- 说话人猜名需要 AI Key，且至少两个说话人各 5 句。
